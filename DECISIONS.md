# Decisions

Continuation of the decision log in `PLAN.md` (D01–D37). Each row records a choice the plan did not
cover, made by the standing rule: (1) fidelity to the original's feel, (2) simplicity, (3) polish.

ID prefixes: **M** sim and mechanics, **L** levels, **R** rendering and camera, **A** audio,
**I** input, **S** storage, **G** game flow and UI, **B** builder, **T** tooling and tests,
**P** public beta and deployment.

## Sim and mechanics

| ID  | Area                      | Decision                                                                                                                                                                   | Rationale                                                                                                                      |
| --- | ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| M01 | `dsin` range reduction    | Reduce to [−π, π] as specified, then fold into [−π/2, π/2] using `sin(π − x) = sin x` before the x¹¹ Taylor polynomial                                                     | The plain polynomial loses accuracy near ±π; folding keeps the error below 1e-7 with only `+ − * /`                            |
| M02 | `datan2`                  | Odd minimax polynomial for atan on [0, 1] (Abramowitz & Stegun 4.4.49 coefficients) with octant reduction                                                                  | The plan names `datan2` but no formula; this is accurate to ~1e-8 and deterministic                                            |
| M03 | Determinism lint          | ESLint `no-restricted-properties` bans `Math.sin/cos/tan/atan/atan2/exp/log/pow/hypot/cbrt/random`, `Date.now` and `performance.now` in `src/sim`, `src/level`, `src/core` | Enforces D06 at edit time; an enforcement test repeats the check for `src/sim` and `src/core`                                  |
| M04 | Wave floor edges          | The wave amplitude tapers linearly to zero over the outermost cell of the region                                                                                           | Without a taper the wave floor forms a step against neighbouring terrain that reads as a phantom wall                          |
| M05 | Jump gaps in passability  | The "jump edge" rule (§6.5) accepts gaps of one or two void cells when the far slab is ≥ 0.5 lower and the near edge is open                                               | Race 4's runway gap is two cells wide by design (§8.4); one-cell-only analysis reported E008 for a solvable level              |
| M06 | Leaving a moving platform | A marble that leaves a carrier keeps the carrier's velocity                                                                                                                | Matches physical intuition; without it, riders stop dead when they roll off the deck                                           |
| M07 | Autopilot and held states | Entering a pipe, funnel or catapult counts as reaching the current waypoint                                                                                                | The marble is taken out of the autopilot's control there; waiting for it to "arrive" would stall the solution                  |
| M08 | Step-wall test on ramps   | Compare the neighbour's edge height against max(marble z, own cell's edge height at that point)                                                                            | Comparing against marble-centre z made every gentle ramp seam a phantom wall (0.175 > 0.15 threshold)                          |
| M09 | Hunter steelie pinning    | After a ram (impact > 0.3) a hunting steelie stops chasing for 60 ticks; ram events only fire above that impact                                                            | Without recoil a mass-3 hunter could pin a marble against a wall forever and spam ram audio every tick                         |
| M10 | Autopilot and platforms   | While the current waypoint has no ground, or is on a platform with void between marble and target, the autopilot holds (riding any carrier)                                | Fixed holds cannot stay in phase with platforms after deaths or hoover drift; waiting on sim state is deterministic and robust |
| M11 | Landing from below        | An airborne marble lands only if it was at most 0.5 below the surface on the previous tick (LAND_SNAP)                                                                     | Prevents a platform sliding over a falling marble from teleporting it up onto the deck                                         |
| M12 | W101 and acid             | Acid cells are excluded from the "unreachable cell" warning                                                                                                                | Acid is meant to be avoided, so unreachability is expected                                                                     |
| M13 | Hoover pull vs. friction  | The pull follows §7.10 exactly (linear fall-off to zero at `pullRadius`), so near the edge of its radius a hoover cannot move a marble at rest against rolling friction    | Faithful to the spec; a rolling marble is still deflected, and a marble well inside the radius is drawn in                     |

## Rendering and camera

| ID  | Area                  | Decision                                                                                                                                    | Rationale                                                                                                    |
| --- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| R01 | Strip cache           | Each strip is cached in 4-cell segments, each sized to exact corner and face heights, evicted least-recently-used per segment               | Whole-strip canvases would blow the 64 MB cap at devicePixelRatio 2; 4 cells used about half the memory of 8 |
| R02 | Sphere depth          | A sphere's anchor moves one cell toward the viewer on an axis where it overhangs a neighbour no higher than itself                          | Plain `floor(x)+floor(y)` lets a flat neighbouring cell paint over the marble's edge                         |
| R03 | Rails                 | South and east rails are drawn in strip k+1, before that strip's cells                                                                      | A marble in the rail's own cell is then correctly drawn behind it                                            |
| R04 | Platforms             | Platforms are drawn as one piece per cell, each anchored at the furthest cell it touches; a marble riding on top shares that piece's anchor | Terrain under the platform can't overdraw it, and riders draw on top                                         |
| R05 | Goal ring             | The goal ring is drawn once per strip it crosses, clipped to that strip's horizontal band                                                   | The ring spans several strips but must still sort correctly against marbles                                  |
| R06 | Funnel                | Funnel cells are cached at 8×8 subdivision with smooth shading; the six rings are exact ellipses on the cone                                | Banding per sub-square looked stair-stepped                                                                  |
| R07 | Faces next to waves   | A cached cell's side face next to a wave cell extends down to that neighbour's lowest possible height                                       | The live wave cell, drawn later, then always covers the gap                                                  |
| R08 | Void faces            | The side-face fade over void runs perpendicular to the face's top edge, not straight down                                                   | Straight-down fades showed banding between neighbouring cells                                                |
| R09 | Acid and speed decals | Acid bubbles and speed chevrons are computed from time each frame rather than spawned as particles                                          | No allocation, and stable on large acid fields                                                               |
| R10 | Static scenes         | `drawStatic` builds a rest-state snapshot of the entities and animates waves from render time                                               | The title backdrop and builder preview look alive with no sim running                                        |
| R11 | Wave rendering        | The renderer samples the same tapered `waveEnvelopeOffset` as the sim                                                                       | Raw offsets drew steps at region edges that the marble never feels                                           |
| R12 | Camera after holds    | `transit` counts as a held state like `dying`/`waiting`; after any held state the camera uses the slower 0.3 s follow                       | Gives a smooth pan from pipe entry to exit                                                                   |
| R13 | 2P single framing     | If only one marble can be framed, the camera follows it at zoom 1, with the velocity lead only when the other player is eliminated          | Matches "1P-style" in §7.9                                                                                   |
| R14 | World canvas          | `GameShell` renders the single `<canvas id="world">`; `index.html` only provides `#app`                                                     | One owner for size and DPR handling; the builder's iso view creates its own canvas                           |

## Audio

| ID  | Area         | Decision                                                                                                                                                           | Rationale                                                      |
| --- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| A01 | Hoover death | Added a `hooverSuck` sound (noise sweep up plus a falling sine)                                                                                                    | The SFX table has no one-shot hoover death sound               |
| A02 | Fall death   | A `fall` death plays `shatter` at 0.6 gain                                                                                                                         | The table doesn't map `fall`                                   |
| A03 | Clack limit  | Clacks are limited to one per player every 40 ms                                                                                                                   | Corner wall passes can fire several clacks per tick            |
| A04 | Pipe sweep   | The pipe/funnel sweep uses the `travelTime` of the entry nearest the player's last known position                                                                  | `pipeEnter`/`funnelEnter` events don't say which entity        |
| A05 | Track data   | `TrackDef` gains `leadDensity`, `leadOctave`, `padGain`, `highpass` (airy m4) and `bassWobble` (m5); bass pattern letters are x root, o fifth, + octave, w walking | Encodes the table's "character" column as data                 |
| A06 | Early music  | `startMusic` before `unlock()` is remembered and starts on unlock                                                                                                  | The title music can be requested before the first user gesture |

## Input

| ID  | Area             | Decision                                                                                                                                                        | Rationale                                                                         |
| --- | ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| I01 | Keyboard         | Keys are identified by `KeyboardEvent.code`, not by the typed character                                                                                         | Works the same on non-QWERTY layouts                                              |
| I02 | Keyboard ramp    | The magnitude ramps only while the held keys give a non-zero direction; opposite keys (left+right) give zero and no ramp                                        | Stops a hidden full-strength ramp from building up while the keys cancel out      |
| I03 | Keyboard decay   | After release, the decay keeps the last direction; Numpad 5 is ignored                                                                                          | Makes "taps give small nudges" work as the spec describes                         |
| I04 | Keyboard reset   | `reset()` clears the ramp but keeps the set of held keys; window blur releases all keys                                                                         | A key held through the countdown or pause still works; blur prevents stuck keys   |
| I05 | Key handling     | No `preventDefault` on keys; keydown events from input, textarea, select or editable elements are ignored                                                       | Doesn't interfere with menus, initials entry, or builder fields                   |
| I06 | Pointer lock     | The manager never requests pointer lock by itself; the caller calls `requestPointerLock()` from a click                                                         | The game controller decides when locking is appropriate                           |
| I07 | Mouse fallback   | Absolute fallback starts on lock failure or when lock is unavailable, and ends on the next successful lock; it steers only while the pointer is over the target | Keeps the fallback contained; the HUD gets a simple coordinate frame for the ring |
| I08 | Esc while locked | `onPauseRequest` fires only when the lock ends without our own `exitPointerLock()`                                                                              | Browsers swallow Esc while locked; this avoids a double pause                     |
| I09 | Pad numbering    | "Pad 0/1" means the first and second connected pads, not `Gamepad.index`                                                                                        | Browsers can leave gaps in the `getGamepads()` array                              |
| I10 | Stick flicks     | Menu flicks fire at 0.6 on the dominant axis and re-arm below 0.35; a pad's buttons don't fire on the first poll after it connects                              | Hysteresis stops repeat events; no phantom presses on connect                     |
| I11 | Pad edges        | `sample(0)` takes queued pad presses and turns a pause press into `onPauseRequest`; menus use `pollButtons()`; `reset()` keeps held state                       | One edge tracker, no double pause, and a held button doesn't re-fire after reset  |
| I12 | Touch            | A tap is a touch ending within 350 ms with under 16 px of movement; only the first touch in the left zone drives the stick                                      | Standard tap thresholds                                                           |

## Storage

| ID  | Area        | Decision                                                                                                                                                      | Rationale                                                                    |
| --- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| S01 | High scores | A table with fewer than 10 rows accepts any score above 0; initials are padded with "A"; seeded dates are a fixed ISO string                                  | The plan doesn't cover short tables; keeps seeds deterministic               |
| S02 | Custom list | `listCustomLevels` is sorted newest first; re-putting a level keeps its `addedAt` and `bestTicks`                                                             | Natural list order; a re-import keeps the player's history                   |
| S03 | Duplicates  | `duplicateDraft` gives the copy a new draft id, the name "`<name>` copy" (cut to 24 chars), and a unique level id like `<id>-copy` or `-copyN` (max 48 chars) | Both drafts can later exist side by side as custom levels without collisions |

## Builder

| ID  | Area                | Decision                                                                                                                                                           | Rationale                                                                                                       |
| --- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| B01 | Panning keys        | Arrow keys pan the top-down view (or pick the direction when the slope/speed-strip tool is active); WASD panning is not offered                                    | W, S and A are tool keys in §6.2 (Wall, Slope, Auto-solve)                                                      |
| B02 | Set-height digits   | With the Set Height tool active, digit keys type the height value; otherwise 1 and 2 select the P1/P2 start tools                                                  | Both bindings are in §6.2; the active tool disambiguates                                                        |
| B03 | Test-play timing    | Builder test-play skips the countdown, so tick 0 of a recording is GO                                                                                              | The recorded replay then aligns with how `mmlevel` replays solutions                                            |
| B04 | Save recording      | After a recorded test-play reaches the goal, a modal offers "Save as solution" or "Discard"                                                                        | Explicit, and it does not overwrite the waypoint solution by accident                                           |
| B05 | No confirm dialogs  | Builder edits never ask for confirmation (except resizing the grid smaller); undo covers mistakes. Replacing a non-waypoint solution with a waypoint shows a toast | Keeps editing fast; a 200-step undo history makes confirmations redundant                                       |
| B06 | Entity path mode    | Placing an entity enters "click path cells" mode only when its path is required (platform); optional paths are edited in the inspector                             | The common case stays one click                                                                                 |
| B07 | Lazy builder bundle | The builder is code-split and loaded on demand; `verifyCompiled` lives in a YAML-free module                                                                       | Keeps the `yaml` parser out of the game bundle (D13); the main bundle is ~490 KB including every compiled level |
| B08 | Fit on open         | The top-down view fits the whole grid the first time a draft opens                                                                                                 | A 36×64 grid at the default 24 px is larger than most screens                                                   |
| B09 | Slope arrows        | Slope arrows in the top-down view point downhill (slope codes name the descending direction)                                                                       | Matches §5.2 and reads like a fall line                                                                         |
| B10 | Physics fields      | Inspector ranges follow the schema per key: `slopeGravityScale` −1..2, `frictionScale` 0.25..3, `inputScale` 0.5..1.5                                              | A single 0.5..1.5 range made the inverted-gravity fixture unrepresentable in the GUI                            |
| B11 | Autosave            | Drafts autosave every 30 s and when the tab is hidden or loses focus                                                                                               | No lost work, without writing to IndexedDB on every stroke                                                      |

## Tooling and tests

| ID  | Area                | Decision                                                                                                                                                                                                                                                                    | Rationale                                                                                                            |
| --- | ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| T01 | ESLint hooks plugin | `eslint-plugin-react-hooks` v5 (flat-config native) with `rules-of-hooks` as error; CLI helpers avoid the `use*` prefix                                                                                                                                                     | v4 has no flat config; the rule treats any `use*` function as a hook                                                 |
| T02 | E2E scope           | §10 is absent from the plan, so the E2E suite is defined here: boot, settings/scores navigation, race + input + HUD, pause, timeout → high-score flow, per-browser replay determinism, builder new → auto-solve → export → play, Tab to iso view, and a canvas sanity check | Covers every flow the D25/D37 hooks were designed for                                                                |
| T03 | Visual tests        | Visual checks assert the world canvas draws a varied, opaque picture rather than comparing pixel baselines                                                                                                                                                                  | Baselines differ per OS and browser engine and would fail in CI on a different platform                              |
| T04 | Perf project        | The Playwright perf spec runs in its own chromium project that depends on the three E2E projects; the budget is ≤ 8 ms of work per frame on Ultimate                                                                                                                        | Frame timing is meaningless while other browsers compete for CPU; work per frame is stable headless                  |
| T05 | Sim benchmark       | A Vitest benchmark requires < 0.25 ms per tick for every race's replay and 60 s of 2P Ultimate in < 1 s                                                                                                                                                                     | Two ticks per 60 fps frame then use < 3% of the frame                                                                |
| T06 | Freshness test      | The enforcement suite recompiles every source into a temp dir and deep-compares it with `levels/compiled` (files and manifest)                                                                                                                                              | Catches hand edits and stale outputs without touching the working tree                                               |
| T07 | Bundle test         | An enforcement test walks the static import graph from `src/main.tsx` and fails if it reaches `yaml`, `src/level/parse.ts` or `src/builder/`                                                                                                                                | Locks in B07 so the game bundle cannot regress                                                                       |
| T08 | Mobile E2E          | Four extra Playwright projects (Pixel 7 and iPhone 14, portrait and landscape) run `tests/e2e/mobile.spec.ts` via `npm run test:e2e:mobile`, outside the default `test:e2e`. Chromium gets real touches through CDP; WebKit gets synthetic touch events on the canvas       | WebKit has no `Touch` constructor and Playwright has no touch-drag API; keeps the default suite's run time unchanged |

## Public beta and deployment

| ID  | Area                | Decision                                                                                                                                                                                                                                                                                                  | Rationale                                                                                                                                                                                                                                         |
| --- | ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P01 | Hosting             | _Superseded by P09._ Firebase Hosting site `marble-melancholy` in the existing GCP project `development-262721`                                                                                                                                                                                           | Free tier, automatic TLS for custom domains, cache headers in `firebase.json`, no new billing project. A Cloud Storage bucket behind an HTTPS load balancer would cost about $18/month for the forwarding rule, and the GKE cluster was ruled out |
| P02 | Domain              | `marble.llmgag.world`                                                                                                                                                                                                                                                                                     | A subdomain of the domain the llmgag project uses. Its DNS is hosted by Squarespace Domains (ex-Google Domains, `ns-cloud-d*.googledomains.com`), not in a Cloud DNS zone gcloud can reach, so the records are added by hand                      |
| P03 | Deployer            | _Superseded by P11._ `npm run deploy` runs `tools/deploy/hosting.ts`, which calls the Firebase Hosting REST API with a `gcloud auth print-access-token` token                                                                                                                                             | Reuses the gcloud login the developer already has, with no `firebase-tools` dependency or separate `firebase login`. `firebase.json` stays the source of truth, so `firebase deploy --only hosting` is equivalent                                 |
| P04 | Cache headers       | `/` and `/index.html` are `no-cache`; `/assets/**` is `public, max-age=31536000, immutable`                                                                                                                                                                                                               | Vite hashes asset names, so only the HTML needs revalidation and testers get a new build on the next load                                                                                                                                         |
| P05 | Build label         | The title screen shows `BETA <package version> · <git short sha>`, with `+dirty` when the tree has uncommitted changes; the package version stays 1.0.0                                                                                                                                                   | Feedback can name the exact build, and the suffix marks builds that are not reproducible from a commit                                                                                                                                            |
| P06 | Feedback link       | `VITE_FEEDBACK_URL` (build time, http/https only) adds FEEDBACK to the title and pause menus and a small link to the result cards; everything is hidden when it is unset                                                                                                                                  | Menu items work with keyboard, gamepad and touch; result cards advance on their own, so a plain link fits them better                                                                                                                             |
| P07 | Mobile audio unlock | Audio also unlocks on `pointerup`                                                                                                                                                                                                                                                                         | A touch `pointerdown` is not a user activation, so on phones the audio context could never resume. Still gesture-driven, no autoplay                                                                                                              |
| P08 | Portrait phones     | Portrait keeps the letterboxed 16:9 stage and shows a "rotate for a bigger view" hint in the empty bar above it; the stage is sized with `dvh`                                                                                                                                                            | Non-blocking (works with rotation lock on); dynamic viewport units keep the stage clear of mobile browser toolbars                                                                                                                                |
| P09 | Hosting (GKE)       | The beta runs in the GKE cluster `cluster-1` (namespace `marble-melancholy`, one nginx-unprivileged pod) behind the shared Gateway `default/external-https`, attached with an HTTPRoute from its own namespace. Firebase was removed and its two APIs disabled                                            | The user preferred the existing cluster over Firebase. Reusing the Gateway the llmgag hosts already use adds no load balancer, so the cost is a 10m CPU / 32Mi pod on an existing node                                                            |
| P10 | TLS (GKE)           | Google-managed Certificate Manager certificate `marble-llmgag-world` with DNS authorization `dns-authz-marble-llmgag-world`, added as one entry to the Gateway's shared cert map `dslama-net-map`                                                                                                         | Same mechanism as the llmgag hosts. DNS authorization lets the certificate issue before the A record points at the load balancer. Adding a map entry is additive and leaves the IP and the other entries untouched                                |
| P11 | Deployer (GKE)      | `npm run deploy` builds dist/, builds a linux/amd64 image with `docker buildx`, pushes it to Artifact Registry `marble-melancholy/web:<git sha>` (with `-dirty-<time>` for uncommitted trees), applies `deploy/k8s/marble.yaml` with that tag and waits for rollout. kubectl is pinned to the GKE context | The Mac is arm64 and the node is amd64. Unique tags force a rollout on every deploy. Pinning the context means a deploy can never reach the DigitalOcean cluster                                                                                  |
| P12 | Image               | nginx-unprivileged 1.27-alpine serving the prebuilt dist/, non-root (uid 101), read-only root filesystem with an emptyDir at /tmp, `/healthz` for the probes and the GKE HealthCheckPolicy, gzip on                                                                                                       | Smallest moving parts for a static site. The cache headers match P04                                                                                                                                                                              |
